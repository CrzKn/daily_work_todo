## 1. 项目概述

**Daily Work Todo** 是一个轻量级个人任务管理系统。

- **目标用户**：个人用户（单用户场景，无登录体系、无权限分级）
- **核心价值**：以看板直观展示任务在各状态下的分布，支持拖拽流转、标签归类、优先级标识，可按周期自动生成任务，并可回看已归档任务
- **核心旅程**：进入系统 → 任务看板 → 新建任务 → 按优先级/标签组织 → 拖拽流转状态 → 完成后次日自动归档
- **周期任务旅程**：新建周期规则 → 设置每日/每周/每月规则与开始日期 → 打开系统时生成当天到期任务 → 每期任务独立处理
- **归档回看旅程**：进入「已归档任务」→ 按关键字/优先级/标签/归档时间筛选 → 打开只读详情回顾

## 2. 核心对象与字段

### 2.1 任务（personal_task）

| 字段 | 类型 | 可空 | 说明 | 实现状态 |
|------|------|------|------|----------|
| pt_id | VARCHAR(32) | 否 | 主键，`ASSIGN_UUID` 生成 32 位无连字符 UUID | 已实现 |
| title | VARCHAR(200) | 否 | 任务标题，前端限制 200 字 | 已实现 |
| content | TEXT | 是 | 任务正文，纯文本；新建/编辑时非必填 | 已实现 |
| tag_id | VARCHAR(255) | 是 | 标签 ID，**多个标签以英文逗号分隔存储**（兼容旧的单标签数据） | 已实现 |
| priority_id | VARCHAR(32) | 是 | 关联优先级 ID | 已实现 |
| pt_status_id | VARCHAR(32) | 是 | 关联任务状态 ID | 已实现 |
| created_tme | DATETIME | 否 | 创建时间，后端写入当前时间 | 已实现 |
| updated_time | DATETIME | 是 | 更新时间，更新接口写入当前时间；新建时显式为 null | 已实现 |
| archived_time | DATETIME | 是 | 归档时间，进入历史状态时写入，离开时置空 | 已实现 |
| deadline_time | DATETIME | 是 | 任务截止日期 | **未实现**（实体有字段，无 UI、无接口逻辑、建表脚本无该列） |

**说明**：

- 任务为**物理删除**，删除后不可恢复，无回收站。
- 任务不建立外键；标签、优先级、状态被软删除后，任务保留原 ID，前端按「未设置 / 未分类」展示。
- 多标签采用逗号字符串而非关联表，无索引、无长度校验（受 `tag_id` 字段长度限制）。

#### 3.2.8 自动归档

- 归档时间保持原完成时间不变，保证历史排序稳定

#### 3.3.3 生成机制

- 触发时机：进入任务看板、进入周期任务页、新建/修改规则后、启用规则后，前端调用 `POST /periodicTask/generate`
- 生成范围：**仅生成"今天"到期的任务**，不回补历史日期
- 防重复：`last_generate_date` 记录最近成功生成的计划日期，同规则同日最多一条
- 生成任务继承规则的标题、内容、标签（单个）、优先级；默认状态优先取固定 ID `status_todo`，不存在时取排序最小的状态
- 生成失败写入 `last_fail_date` 并记录日志，列表提示可重试
- 重试仅当"今天"命中规则且当天尚未生成时有效，**跨天失败无法重试**
- **无后台定时任务**：当天未打开系统则不会生成该期任务

**实现状态**：部分实现（缺少定时调度与跨天补生成）。

#### 3.3.4 日期计算规则

- 每日：从开始日期起每天
- 每周：按所选星期几，每周一次
- 每月：按所选日期；当月不存在该日期（如 2 月 30 日、小月 31 日）时**跳过该月，不顺延到月末**
- 下次计划日期 = 不早于开始日期、不早于今天、符合周期条件；若今天已生成则顺延到下一期
- 停用、删除规则不影响已生成任务

**实现状态**：已实现。

## 4. 业务规则汇总

| 规则 | 说明 |
|------|------|
| 任务排序 | 优先级升序 → 创建时间降序 → 更新时间降序 |
| 状态/优先级排序 | 各自排序值升序 |
| 颜色 | 优先级按排序值插值（红→绿），不存储固定色值 |
| 默认状态 | 新建任务进入排序值最小的状态 |
| 归档时间 | 由非历史状态进入历史状态时写入；离开时清空；历史状态间流转不变 |
| 自动归档 | 已完成的往日任务在读取列表时自动转为已归档 |
| 删除-任务 | 物理删除，不可恢复 |
| 删除-标签/状态/优先级 | 软删除，不再出现在列表与筛选项；关联任务展示降级 |
| 历史范围 | 当前实现仅 `status_archived` 状态的任务 |
| 校验 | 任务标题必填；周期规则标题与内容必填；字典名称、排序必填 |
| 周期生成 | 仅当天、仅一次、不回补；先固定 `status_todo`，缺失时取排序最小状态 |
| 周期删除/停用 | 仅停止后续生成，已生成任务不受影响 |

## 6. 当前实现边界与已知限制

> 本章为现状说明，不是目标需求；对应改进项见第 7 章。

| 编号 | 限制 | 影响 |
|------|------|------|
| L-01 | 看板只看 `status_archived` 固定 ID 决定隐藏列，历史接口也只查该固定 ID | 改名/更换 ID、或自定义历史状态后，看板与归档页行为不符合 `is_history` 配置 |
| L-02 | 自动归档写死 `status_done` → `status_archived` | 自定义「已完成」类状态永不自动归档 |
| L-03 | 新任务默认落到排序最小状态；若该状态为已归档，任务创建后不可见 | 用户误以为创建失败 |
| L-04 | 归档任务无恢复入口（看板隐藏归档列、历史页只读、详情无状态字段） | 误归档只能删除重建 |
| L-05 | `deadline_time` 仅有实体字段 | 无截止日期、逾期提示、按截止排序 |
| L-06 | 周期任务无后台调度，只在页面访问时生成当天任务 | 当天未打开系统则该期任务永久缺失且不补 |
| L-07 | 周期失败重试仅限当天 | 跨天失败无法补生成 |
| L-08 | 周期规则内容仍强制必填 | 与任务内容非必填不一致 |
| L-09 | 周期规则标签为单选 | 与任务多标签能力不一致 |
| L-10 | 标签以逗号字符串存储 | 无索引、无外键、无长度校验、难以统计 |
| L-11 | 已归档列表无状态筛选 | 与早期需求 3.7.4 不一致 |
| L-12 | 看板无关键字搜索；看板与周期列表无分页 | 数据量增长后查找与加载效率低 |
| L-13 | 历史分页为前端分页，数据仍全量加载 | 大量归档数据时首屏变慢 |
| L-14 | 读接口内做批量写（自动归档） | 读请求有副作用，不利于缓存与并发 |
| L-15 | `schema.sql` 未包含 `is_history`、`archived_time`、`deadline_time`，且 `content` 为 NOT NULL | 全新建库与代码/实际库不一致，依赖多个手写脚本 |
| L-16 | 接口统一返回 `boolean`/裸数据，无统一错误码与异常处理 | 前端只能提示「后端返回失败」，无法区分原因 |
| L-17 | 无鉴权、数据库密码明文、生产日志打印 SQL | 仅适合本机/内网单用户使用 |
| L-18 | 无自动化测试（仅空的上下文加载测试） | 归档、周期日期等边界规则容易回归 |
| L-19 | 无服务端分页/搜索接口；周期规则列表无查询条件 | 扩展性与大数据量支持不足 |
| L-20 | 看板列收起状态、筛选条件均不持久化 | 刷新后需要重新操作 |

### 7.2 P0 需求明细

#### R-01 归档任务恢复

- **背景**：任务进入已归档后在看板不可见、历史页只读，无法回到进行中。
- **需求**：
  1. 已归档列表行操作或只读详情中提供「恢复」入口，恢复时选择目标状态（限未删除且非归档状态）。
  2. 恢复后清空 `archived_time`，任务重新出现在看板对应列。
  3. 也支持在已归档列表批量恢复。
- **验收**：恢复后看板立即可见；刷新后仍在目标状态；历史列表不再出现该任务。

#### R-02 任务截止日期

- **背景**：`deadline_time` 字段存在但无任何入口。
- **需求**：
  1. 新建任务、任务详情支持设置/清除截止日期（日期+时间，可空）。
  2. 看板卡片与已归档列表展示截止日期；逾期任务显示红色「已逾期」标记。
  3. 支持按截止日期排序或筛选「今日到期 / 已逾期 / 未来 7 天」。
  4. 数据库补列并提供幂等变更脚本。
- **验收**：截止日期可保存、清除；逾期标记与筛选结果正确；历史数据无截止日期时正常展示。

#### R-03 周期任务定时生成与补生成

- **背景**：当前只在访问页面时生成当天任务，未打开系统即漏生成。
- **需求**：
  1. 后端增加定时任务（如每日 00:05 执行），无需用户访问即可生成到期任务。
  2. 支持补生成：对启用规则，从 `max(开始日期, 上次生成日期+1期)` 到今天的每个到期日各生成一条，且受「不回补规则创建前日期」约束。
  3. 补生成需幂等，多实例部署下不重复生成。
  4. 周期列表展示「待补生成」数量并提供手动「立即生成」。
- **验收**：停用前错过的当期在重新启用后可按配置补生成；定时任务日志可见；重复执行不产生重复任务。

#### R-04 已归档列表状态筛选

- **需求**：增加「状态」单选筛选（仅列出 `is_history=1` 且未删除的状态，默认全部），与其他筛选项为「与」关系。
- **验收**：选择状态后列表与总数即时更新；重置后恢复全部。
