> 基于现有代码结构梳理，覆盖所有已实现的功能模块。

## 1. 项目概述

**Daily Work Todo** 是一个轻量级个人任务管理系统，提供任务看板、周期任务、历史任务回看、标签管理、状态管理、优先级管理六大功能模块。

- **目标用户**：个人用户（单用户场景，无登录体系）
- **核心价值**：以看板直观展示任务在各状态下的分布，支持拖拽流转、标签归类、优先级标识，可按周期自动生成任务，并可按条件回看已结束的历史任务
- **核心旅程**：进入系统 → 查看看板 → 新建任务 → 按状态/优先级/标签组织 → 拖拽流转状态
- **周期任务旅程**：新建周期规则 → 设置每日/每周/每月规则与开始日期 → 系统按计划日期自动生成看板任务 → 每期任务独立处理
- **历史回看旅程**：进入历史任务回看 → 按关键字/状态/优先级/标签/归档时间筛选 → 打开只读详情回顾任务

**角色与权限**：系统为个人使用，所有功能对所有使用者开放，无权限分级。

### 2.5 周期任务规则

周期任务规则是生成任务的模板，本身不是某一期具体任务。系统按规则在计划日期生成一条普通任务，写入现有任务表；生成后的任务独立编辑、流转和删除。

表名：`periodic_task`，建表语句见 [periodic_task.sql](file:///d:/AIprojects/Daily_Work_Todo/sql/periodic_task.sql)。

| 字段 | 类型 | 可空 | 默认值 | 说明 |
|------|------|------|--------|------|
| periodic_task_id | VARCHAR(32) | 否 | — | 主键，UUID |
| title | VARCHAR(200) | 否 | — | 任务标题，生成任务时使用 |
| content | TEXT | 否 | — | 任务内容，生成任务时使用 |
| tag_id | VARCHAR(32) | 是 | NULL | 关联标签ID |
| priority_id | VARCHAR(32) | 是 | NULL | 关联优先级ID |
| cycle_type | VARCHAR(10) | 否 | — | 周期类型：DAILY 每日、WEEKLY 每周、MONTHLY 每月 |
| weekly_day | TINYINT UNSIGNED | 是 | NULL | 每周执行日，1=周一 … 7=周日；`cycle_type=WEEKLY` 时必填 |
| monthly_day | TINYINT UNSIGNED | 是 | NULL | 每月执行日，1～31；`cycle_type=MONTHLY` 时必填 |
| start_date | DATE | 否 | — | 开始日期，规则最早生效的自然日 |
| enable_status | TINYINT | 否 | 1 | 启用状态：1 启用、0 停用 |
| last_generate_date | DATE | 是 | NULL | 最近一次成功生成的计划日期，用于防止同一期重复生成 |
| last_generate_task_id | VARCHAR(32) | 是 | NULL | 最近一次生成的任务ID，用于来源追溯 |
| last_fail_date | DATE | 是 | NULL | 最近一次生成失败的计划日期，用于失败提示与重试 |
| delete_status | TINYINT | 否 | 0 | 软删除标记：0 未删除、1 已删除 |
| created_time | DATETIME | 否 | 当前时间 | 创建时间 |
| updated_time | DATETIME | 否 | 当前时间 | 更新时间，更新时自动刷新 |

**设计说明**：

- 周期条件拆分为 `cycle_type` + `weekly_day` + `monthly_day`：每日不填条件字段；每周填星期几；每月填日期。应用层按周期类型校验，保证同一规则只使用其中一个条件字段。
- 防重复生成：以 `last_generate_date` 记录最近一次成功生成的计划日期，同一规则同一日期最多生成一条任务。即使该期任务被删除，此字段也不回退，因此不会重复生成。
- 失败重试：生成失败时写入 `last_fail_date`，周期任务列表据此提示并允许重试；重试成功后清空该字段。
- 不存储「下次计划日期」：由 `start_date`、周期条件与 `last_generate_date` 实时计算，避免修改规则后产生冗余脏数据。
- 不建立外键：与现有表保持一致。标签或优先级被删除后规则继续有效，生成任务时对应字段按未设置处理。
- 软删除：沿用现有 `delete_status` 约定；停用、删除规则均不影响已生成的任务实例。
- 索引：`idx_enable_last_generate` 支持按启用状态和上次生成日期扫描待生成规则；`idx_start_date` 支持按开始日期筛选。

## 3. 系统功能模块

### 3.1 侧边导航

**功能描述**：
- 左侧固定侧边栏，展示系统标题「Daily Work Todo」和六个功能入口
- 点击模块切换右侧内容区
- 当前选中模块高亮（蓝底白字）

**模块列表**：
1. 任务看板
2. 周期任务
3. 历史任务回看
4. 标签管理
5. 任务状态管理
6. 任务优先级管理

---

### 3.2 任务看板（核心功能）

#### 3.2.1 看板概览

**功能描述**：
- 以看板（Kanban）形式展示所有任务，每一列对应一个任务状态
- 列按「任务状态管理」中的排序值升序排列
- 每列头部显示：状态名称、圆点色标、该状态下任务数量、收起/展开按钮
- 无分类的任务归入「未分类」列（灰色）
- 看板横向滚动，当状态数量超出视口宽度时可左右滑动

#### 3.2.2 任务卡片

**功能描述**：
- 每个任务以卡片形式展示在对应状态列下
- 收起模式下仅显示标题和创建日期
- 展开模式下额外展示内容摘要（截断为 60 字符）、优先级标签、标签
- 优先级标签根据优先级排序值动态计算颜色：数值越小越接近红色、越大越接近绿色
- 卡片可拖拽，拖拽时透明度降低，目标列高亮边框

#### 3.2.3 拖拽修改状态

**功能描述**：
- 卡片支持拖拽，拖动到目标状态列即可修改任务状态
- 拖动过程中若鼠标进入看板左右边缘（80px 以内），看板自动横向滚动，速度随距边缘距离递增（最大 20px/帧）
- 拖拽完成后保存状态变更，保存失败时回滚至原状态并提示
- 支持 ESC 键取消下拉、关闭弹窗

**业务规则**：
- 同一状态列内放置不触发更新
- 拖拽完成后刷新数据，任务按后端排序规则重新排列

#### 3.2.4 新建任务

**功能描述**：
- 点击右上角「+ 新建任务」按钮打开新建弹框
- 表单字段：任务标题（必填，最多 200 字）、任务内容（必填，多行文本）、优先级（可选）、标签（可选）
- 标题或内容为空时弹出提示
- 提交成功后自动刷新看板，任务卡片出现在默认状态列中

**系统自动处理**：
- 创建时间写入当前时刻
- 自动分配排序值最小的状态作为默认状态（无任何状态时不分配）
- 优先级/标签未选择时按未设置处理

#### 3.2.5 任务详情弹框

**功能描述**：
- 点击任意任务卡片弹出详情弹框
- 弹框字段：任务标题、任务内容、优先级（自定义下拉）、标签（下拉选择）、创建时间（只读）、更新时间（只读）
- 支持直接在弹框内编辑并保存

**优先级自定义下拉**：
- 触发器保持与普通输入框一致的视觉样式
- 展开后选项以与卡片相同的彩色胶囊展示（颜色规则与卡片一致）
- 支持选择「不设置」清除优先级
- 下拉面板跟随触发框定位，不被弹框滚动区域遮挡
- 点击外部遮罩、按 ESC 或弹框滚动时自动关闭下拉

**保存逻辑**：
- 保存成功后刷新看板数据，并同步弹框内的最新更新时间
- 优先级/标签未选择时按未设置提交

**删除确认**：
- 弹框底部有「删除」按钮
- 点击后弹出二次确认对话框
- 确认删除后从列表中移除并关闭弹框

#### 3.2.6 任务排序规则

看板任务列表按以下优先级排序：

1. 优先级排序值升序（数值越小越靠前，未设置优先级排最后）
2. 创建时间降序（新创建的靠前）
3. 更新时间降序（最近更新的靠前）

#### 3.2.7 快捷键

| 快捷键 | 触发场景 | 行为 |
|--------|----------|------|
| ESC | 删除确认弹框 | 取消删除 |
| ESC | 新建任务弹框 | 关闭弹框 |
| ESC | 优先级下拉展开中 | 关闭下拉 |
| ESC | 任务详情弹框 | 关闭弹框 |

### 3.6 周期任务

**功能描述**：
- 通过侧边导航「周期任务」进入，列表展示任务标题、周期规则、开始日期、下次计划日期、启用状态、创建时间
- 支持新建、修改、停用/启用、删除；删除需二次确认，仅停止后续生成，已生成任务保留
- 进入周期任务页或任务看板时，系统自动检查并生成当天到期的任务

**表单字段**：

| 字段 | 必填 | 说明 |
|------|------|------|
| 任务标题 | 是 | 最多 200 字 |
| 任务内容 | 是 | 多行纯文本 |
| 优先级 | 否 | 不设置时生成任务不关联优先级 |
| 标签 | 否 | 不设置时生成任务不关联标签 |
| 周期类型 | 是 | 每日、每周、每月 |
| 开始日期 | 是 | 默认当天 |
| 每周执行日 | 每周时必填 | 周一至周日任选一天 |
| 每月执行日 | 每月时必填 | 1～31 |

- 表单实时预览周期规则和下次计划日期
- 编辑保存只影响后续生成，不修改已生成任务

**日期规则**：
- 每周按所选星期几重复；每月按所选日期生成，当月不存在该日期时跳过（如每月 31 日避开小月，2 月无 30 日则不生成）
- 不补生成规则创建前或已错过的历史日期
- 同一规则同一计划日期最多生成一条任务；删除当期任务后不重新生成

**生成规则**：
- 生成的任务继承规则的标题、内容、标签、优先级，进入生成时排序值最小的状态
- 生成后的任务按普通看板任务独立编辑、流转和删除
- 生成失败时列表显示「本期生成失败」并提供重试

### 3.7 历史任务回看

#### 3.7.1 功能描述

- 通过侧边导航「历史任务回看」进入，以只读列表形式回看已结束的任务
- 支持按关键字、状态、优先级、标签、归档时间范围筛选，默认按归档时间倒序展示
- 点击任意记录打开只读详情弹框，完整回顾任务内容与时间信息
- 模块内不提供新增、编辑、删除入口；需要修改任务时到任务看板操作

#### 3.7.2 历史范围定义

- 任务当前所属状态在「任务状态管理」中被标记为「计入历史回看」（`is_history = 1`）时，该任务属于历史任务
- 系统预置的「已完成」「已归档」默认计入；其余状态默认不计入，可在任务状态管理页调整
- 任务从历史状态拖回非历史状态时，清空归档时间并退出历史列表
- 历史状态之间流转不重置归档时间，保留首次进入历史状态的时间
- 状态被软删除后，其下任务不再计入历史列表（与看板「未分类」逻辑保持一致）
- 看板中删除的任务不再出现在历史列表；周期任务生成的任务进入历史状态后同样出现在历史列表
- 关联的标签、优先级被软删除后，历史列表与详情按「未设置」展示

#### 3.7.3 列表字段与排序

| 字段 | 说明 |
|------|------|
| 任务标题 | 超长时截断展示 |
| 内容摘要 | 截断为 60 字符 |
| 状态 | 当前状态名称 |
| 优先级 | 彩色胶囊，颜色规则与看板一致 |
| 标签 | 标签名称 |
| 归档时间 | `archived_time`，为空时用更新时间兜底展示 |
| 创建时间 | 任务创建时间 |

**排序规则**：
1. 归档时间降序（最近归档的靠前，空值排最后）
2. 创建时间降序
3. 更新时间降序

#### 3.7.4 筛选条件

| 筛选项 | 交互 | 规则 |
|--------|------|------|
| 关键字 | 文本输入 | 匹配任务标题或内容，忽略大小写，输入停止 300ms 后生效 |
| 状态 | 单选下拉 | 仅列出已标记为历史的状态；默认「全部」 |
| 优先级 | 单选下拉 | 默认「全部」 |
| 标签 | 单选下拉 | 默认「全部」 |
| 归档时间 | 开始日期 + 结束日期 | 闭区间，仅填一端时按单边界筛选 |
| 重置 | 按钮 | 清空全部筛选条件并恢复默认排序 |

- 筛选在已加载的历史任务内即时生效，无结果时展示「暂无符合条件的历史任务」
- 列表顶部展示当前筛选结果总数

#### 3.7.5 只读详情

- 点击任意记录打开只读详情弹框，展示：任务标题、任务内容、状态、优先级、标签、创建时间、更新时间、归档时间
- 弹框内所有字段不可编辑，仅提供「关闭」按钮
- 支持点击右上角 ×、按 ESC、点击遮罩空白处关闭（遮罩关闭逻辑与任务详情弹框一致）

#### 3.7.6 数据与接口设计

**数据库变更**（MySQL 8.0）：

```sql
-- 任务状态表：标记是否计入历史回看
ALTER TABLE `pt_status`
  ADD COLUMN `is_history` TINYINT NOT NULL DEFAULT 0 COMMENT '是否计入历史回看：1计入、0不计入';

-- 个人任务表：记录归档时间
ALTER TABLE `personal_task`
  ADD COLUMN `archived_time` DATETIME NULL DEFAULT NULL COMMENT '归档时间，进入历史状态时写入';
```

**初始化数据**：

```sql
-- 预置状态默认计入历史回看（若名称与现状不一致，按实际名称调整）
UPDATE `pt_status` SET `is_history` = 1 WHERE `pt_status_name` IN ('已完成', '已归档');
```

**归档时间写入规则**：

- 在任务状态更新（看板拖拽）时由后端判断：由非历史状态进入历史状态时写入当前时间；由历史状态进入非历史状态时置空；历史状态之间流转保持不变
- 清空 `archived_time` 需使用 `UpdateWrapper` 显式 `set null`，避免 MyBatis-Plus 默认忽略 null 字段
- 既有任务若其状态被新标记为历史，`archived_time` 为空，前端按更新时间兜底展示与排序

**接口**：

- 新增 `GET /personalTask/history`：返回当前状态 `is_history = 1` 的全部任务（含 `archivedTime`），复用现有任务字段
- 筛选、排序、统计在前端完成；单用户数据量小，本期不分页，后续数据量增长再扩展服务端分页

**任务状态管理联动**：

- 任务状态管理表单增加「计入历史回看」开关，列表增加对应展示列
- 开关变更后无需迁移任务数据，历史列表按最新标记实时计算

## 4. 业务规则汇总

| 规则 | 说明 |
|------|------|
| 排序 | 任务、状态、优先级均按各自排序值升序；任务在同优先级内按创建/更新时间降序 |
| 颜色 | 优先级颜色由排序值插值计算（红→绿），不存储固定色值 |
| 删除-任务 | 删除后不可恢复 |
| 删除-标签/状态/优先级 | 删除后不再展示于列表与任务卡片 |
| 默认状态 | 新建任务自动进入排序值最小的状态 |
| 校验 | 必填项为空时阻止提交并提示 |
| 历史范围 | 仅当前状态标记为「计入历史回看」的任务进入历史列表 |
| 归档时间 | 首次进入历史状态时写入；离开历史状态时清空；历史状态之间流转保持不变 |

### 6.2 边缘自动滚动

- 触发区域：看板容器左右各 80px
- 速度：距边缘越近越快，最快 20px/帧
- 终止条件：鼠标移出触发区、拖拽结束、到达可滚动边界
- 额外保护：纵向离开看板区域 60px 以外时也停止

### 6.3 表单校验

| 页面 | 校验方式 | 提示方式 |
|------|----------|----------|
| 标签/状态/优先级管理 | 必填校验 | 弹框提示 |
| 任务看板新建 | 必填校验 | 顶部消息条 |
| 任务详情保存 | 无额外校验 | 直接保存 |

### 6.4 历史任务回看

- 多个筛选条件之间为「与」关系，任一条件变化后立即刷新结果
- 关键字输入采用 300ms 防抖，避免频繁过滤
- 空状态区分两种文案：没有任何历史任务时提示「暂无历史任务，任务流转到历史状态后会出现在这里」；筛选无结果时提示「暂无符合条件的历史任务」
- 只读详情中的优先级标签颜色与看板、优先级管理页保持一致
